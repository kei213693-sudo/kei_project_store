HS6621 Programming Guide
Bluetooth Low Energy (BLE) 5.0
Bootloader

The HS6621 contains a tiny bootloader which is capable of:

  • Downloading an application via UART/BLE and programming the application image to the flash.
  • Downloading an application to internal SRAM via UART/BLE and executing the application directly.
  • Loading an application located in Flash to internal SRAM and executing the application.
  • Execute an application located in Flash directly.

The GPIO4 is known as BOOT PIN. BOOT PIN can force HS6621 into ISP mode.

The IO of external-flash is:

  • HOLD = IO20
  • CS = IO21
  • MISO = IO22
  • WP = IO23
  • CLK = IO24
  • MOSI = IO25
  • POWER = IO15

HS6621 almost contains internal flash, so most application scenarios do not boot from external flash.

The application's VECTOR_TABLE[10] (defined in startup_xxx.s) is "App Run on SRAM" or "App Run on Flash" flag, If VECTOR_TABLE[10] == 0x46533252, app will run on FLASH directly, otherwise bootloader load FLASH app to SRAM and jump to SRAM.

ISP and BOOT mode

There are two modes in the bootloader: ISP Mode and BOOT Mode.

  • ISP Mode is used for burning application to SFlash or SRAM. Use pmu_force_into_ota_isp_mode() to force chip into ISP mode.
  • BOOT Mode is used for loading application from SFlash to internal SRAM or executing flash application directly.

When the HS6621 is powered on or reset, the bootloader will check the boot pin. If the boot pin is LOW level, HS6621 will be running in ISP mode. If the boot pin is HIGH level and sflash has a valid application, HS6621 will come into BOOT mode, otherwise BURN mode is running.

HS6621 ISP Mode
  • Branch 1: Bootloader burns application image to FLASH.
  • Branch 2: Bootloader burns application image to SRAM.
